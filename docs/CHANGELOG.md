# Changelog

All notable changes should be documented here.

Follow Semantic Versioning.

---

## Version Format

```text
MAJOR.MINOR.PATCH
```

Example:

```text
1.2.0
```

---

## Categories

### Added

New functionality.

### Changed

Behavior improvements.

### Fixed

Bug fixes.

### Removed

Deleted features.

### Security

Security improvements.

### Performance

Optimization work.

### Documentation

Documentation updates.

---

## Release Template

```text
## v1.0.0

Added
-

Changed
-

Fixed
-

Security
-

Performance
-

Documentation
-
```

---

## Rules

Document:

* Features
* Breaking changes
* Database migrations
* Security updates
* Dependency upgrades

Do not include:

* Temporary debugging
* Minor formatting
* Local experiments

---

## Principle

> Every release should tell a clear story of how the platform improved.
